Props tipadas, com valor padrão

o padrão que já existe no Botao.vue, e o padrão novo que o Vue 3.5 do TOKA já suporta

Código real, app/components/base/Botao.vue:

const props = withDefaults(
  defineProps<{
    variante?: 'primario' | 'ghost'
    pill?: boolean
    href?: string
    disabled?: boolean
  }>(),
  {
    variante: 'primario',
    pill: false
  }
)

1. O `?` marca opcional, não o valor padrão

variante?: 'primario' | 'ghost' diz ao TypeScript: essa prop pode não vir. Sozinho, isso não dá valor nenhum quando falta — só permite omitir. O padrão precisa de outra peça.

2. withDefaults — a peça que faltava

Como defineProps<T>() só recebe um tipo (sem espaço pra valores, é só sintaxe TypeScript), o Vue precisa de uma segunda função pra dizer o que usar quando a prop não vem: withDefaults(defineProps<T>(), {...}).

3. O jeito novo — Vue 3.5, que é a versão do TOKA

O TOKA está no Vue 3.5.42 (package.json). Desde a 3.5, "Reactive Props Destructure" é estável: dá pra desestruturar a prop e pôr o valor padrão como o JavaScript já faz em qualquer desestruturação: 

// equivalente ao withDefaults acima, sem precisar dele
const { variante = 'primario', pill = false, href, disabled } =
  defineProps<{
    variante?: 'primario' | 'ghost'
    pill?: boolean
    href?: string
    disabled?: boolean
  }>()

"In 3.5 and above, variables destructured from a defineProps call in <script setup> are reactive." O compilador reescreve variante pra props.variante por baixo dos panos — continua reativo, mesmo parecendo uma variável comum.

— Vue 3.5 announcement, blog oficial

Pegadinha registrada na doc: se você passar a variável desestruturada pra um watch() ou composable e quiser manter a reatividade, precisa envolver num getter: watch(() => variante), não watch(variante).

Botao.vue usa o padrão antigo (withDefaults) — funciona perfeitamente, não tem nada errado. É só mais verboso. Ao escrever componente novo, os dois estilos são válidos; o novo é mais curto porque o projeto já está na versão que suporta.

Pratique — recupere da memória, não releia

1. Por que variante?: 'primario' | 'ghost' tem ? no tipo?
Isso — opcional, pode vir ou não. Sozinho não dá valor nenhum quando falta.
Não. `?` é só "opcional" em TypeScript — não define valor, não restringe tipo além do já declarado.
2. O que withDefaults faz que defineProps sozinho não faz?
Exato — defineProps só declara forma/tipo; withDefaults é quem dá o valor de fallback.
Não. defineProps já declara quais props existem — o que falta é só o valor padrão, que é o trabalho do withDefaults.
3. No Vue 3.5+, o que muda ao usar const { pill = false } = defineProps<...>() em vez de withDefaults?
Isso — o compilador do 3.5 mantém a reatividade, mesmo desestruturado. Efeito idêntico ao withDefaults, só mais curto.
Não. Antes do 3.5 desestruturar quebrava a reatividade — mas isso foi resolvido; hoje o resultado é o mesmo do withDefaults.
Na hora de escrever as props do FichaCabecalho, qualquer dúvida sobre qual dos dois estilos usar — pergunta direto pro Claude no terminal.

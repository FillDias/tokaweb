ref vs computed

a pergunta que decide qual dos dois usar: de onde vem o valor?

Repare numa coisa no SeloCompat.vue da lição 3: ele não tem nenhum ref. Só computed. Isso não é acidente — é a pista de quando usar cada um.

1. ref — a fonte, o dado que você escreve

ref() embrulha um valor num objeto reativo. Você atribui direto: minhaRef.value = novoValor. Sempre que o valor nasce de algo que aconteceu agora — usuário digitou, clicou, a API respondeu — é ref. 

const termoBusca = ref('')
// no template: <input v-model="termoBusca">
// termoBusca.value muda toda vez que o usuário digita

2. computed — o derivado, o que você nunca escreve direto

computed() não guarda um valor próprio — ele calcula a partir de outro dado reativo (um ref, uma prop, outro computed). Cacheado: só recalcula se a dependência mudar (lição 3). 

// SeloCompat.vue — os dois computed dependem só de props,
// nenhum dado local, nenhum ref
const atual = computed(() => config[props.estado])
const rotuloExibido = computed(() => props.texto ?? atual.value.rotulo)

3. Por que SeloCompat não tem ref nenhum

Porque ele não guarda estado próprio. Tudo que ele mostra já existe em algum lugar — vem de props.estado e props.texto, que o componente pai controla. Não há nada que "aconteça" dentro do SeloCompat — ele só reage ao que chega.

Regra prática: se o valor nasce num evento (input, click, resposta de API) → ref. Se o valor já existe em outro lugar e você só está reformatando/combinando → computed.

4. E o cabeçalho da ficha (item 5)?

Pensando no que você vai construir: se o FichaCabecalho só recebe a peça já carregada como prop e mostra o nome, o código, o selo — ele é parecido com o SeloCompat: sem estado próprio, sem ref, só props e talvez computed pra formatar algo. Se em algum momento ele precisar guardar algo que o usuário faz ali dentro (por exemplo, expandir uma seção), aí sim entra ref.

Pratique — recupere da memória, não releia

1. Um <input> de busca guarda o que o usuário está digitando agora. Isso é ref ou computed?
Isso — o valor nasce do evento de digitação, não deriva de outro dado. É exatamente o caso de uso de ref.
Não. O que o usuário digita é o dado de origem, não algo calculado — isso é ref, não computed nem prop.
2. SeloCompat não tem nenhum ref no código. Por quê?
Isso — sem estado próprio, sem evento local, nada pra guardar. Só formatação do que já chegou via props.
Não. Não é sobre tamanho do componente nem restrição técnica — é que ele não tem nenhum dado de origem próprio.
3. Dá pra fazer ref.value = novoValor direto? E computed.value?
Certo — ref é a fonte, você escreve nela. computed (na forma comum, sem setter) é só leitura, é derivado.
Não. ref aceita atribuição direta (é a fonte); computed comum é só leitura, calculado a partir de outra coisa.
Qualquer dúvida sobre onde ref ou computed entram no que você está construindo — pergunta direto pro Claude no terminal antes de escrever o componente.

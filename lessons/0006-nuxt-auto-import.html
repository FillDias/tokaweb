Por que computed nunca precisou de import

o mistério que ficou em aberto desde a lição 3 — e a decisão que você vai tomar agora, no cabeçalho

Na lição 3 você viu computed() sendo usado em SeloCompat.vue sem nenhum import { computed } from 'vue' em lugar nenhum. Isso não é compiler macro (macro é coisa do defineProps, lição 3) — computed é uma função de verdade, que existe em runtime. Então por que funciona?

1. O Nuxt auto-importa três coisas

"Nuxt auto-imports components, composables and Vue.js APIs to use across your application without explicitly importing them."

— documentação oficial do Nuxt

  • Componentes de app/components/
  • Composables de app/composables/
  • APIs do Vue — ref, computed, watch — e composables do próprio Nuxt, tipo useRoute

É por isso que computed "simplesmente funciona".

2. O detalhe que muda tudo: nome de componente tem prefixo de pasta

Auto-import de componente segue uma regra: o nome da tag nasce do caminho do arquivo, removendo repetição.

Um componente em components/base/foo/Button.vue vira <BaseFooButton />.

— documentação oficial do Nuxt

aplicando no toka
app/components/base/BlocoCodigo.vue auto-importado viraria <BaseBlocoCodigo>, não <BlocoCodigo>.
app/components/base/SeloCompat.vue viraria <BaseSeloCompat>.

3. Por que os componentes do TOKA até agora usam import explícito

Em Cabecalho.vue, FaixaVeiculo.vue, CtaFlutuante.vue — todos importam Botao explicitamente: 

import Botao from '~/components/base/Botao.vue'

Isso não é necessário — é uma escolha. Import explícito ignora a regra de prefixo e usa o nome que você quiser. A alternativa seria não importar nada e escrever <BaseBotao> no template.

4. A decisão que sobra pra você, no FichaCabecalho

Ao escrever app/components/peca/FichaCabecalho.vue e usar BlocoCodigo/SeloCompat (que moram em components/base/), você tem três caminhos, todos válidos:

  1. Import explícito, igual ao resto do projeto até agora — <BlocoCodigo> no template
  2. Sem import, usando o nome com prefixo — <BaseBlocoCodigo>
  3. Configurar pathPrefix: false nos components do nuxt.config.ts, pra todo componente do projeto perder o prefixo — inclusive os que já existem

Essa lição não escolhe por você. É uma decisão de convenção do projeto — vale bater com o padrão que já existe antes de decidir.

Pratique — recupere da memória, não releia

1. Um componente em components/base/Botao.vue, sem import, quer aparecer como <Botao>. Funciona sem configuração?
Isso — o nome herda o caminho da subpasta. Sem import ou pathPrefix:false, seria <BaseBotao>.
Não. O componente É auto-importado (não é bloqueado) — só que com nome prefixado pela subpasta, não o nome puro do arquivo.
2. Por que computed() funciona no SeloCompat sem nenhum import declarado?
Exato — é o Nuxt (não o script setup, não o JS) que auto-importa ref/computed/watch do Vue.
Não. Não é palavra reservada nem coisa do script setup — é especificamente o mecanismo de auto-import do Nuxt.
3. Se você configurar pathPrefix: false nos components do Nuxt, o que muda?
Isso — BaseBotao vira Botao, BaseSeloCompat vira SeloCompat, etc. Auto-import continua, só o nome muda.
Não. pathPrefix:false só muda o nome da tag gerada — não desliga o auto-import nem afeta checagem de props.
Quando for decidir entre as três opções da seção 4, me chama — posso mostrar como cada uma fica no seu projeto antes de você escolher. E qualquer dúvida no meio do caminho, pergunta direto.
